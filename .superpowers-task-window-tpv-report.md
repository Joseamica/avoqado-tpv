## Files changed
- `app/src/main/java/com/jaac/avoqado_tpv/core/data/network/dto/TpvSettingsDto.kt`
  Added `promoterLocationStartHour: Int? = null` and `promoterLocationEndHour: Int? = null`
  (`@SerializedName`, same nullable-default pattern as `trackPromoterLocation`). `toDomain()`
  maps `null -> 11` / `null -> 18`. `toDto()` round-trips both fields.
- `app/src/main/java/com/jaac/avoqado_tpv/features/payment/domain/model/TpvSettings.kt`
  Added `promoterLocationStartHour: Int = 11` and `promoterLocationEndHour: Int = 18` to the
  domain model (needed so the worker has something typed to read — this is the "domain mapping
  file" referenced in the task, since `toDomain()`/`toDto()` live in the DTO file but the domain
  model itself needed the new fields to carry the values).
- `app/src/main/java/com/jaac/avoqado_tpv/core/location/PromoterLocationGate.kt`
  `shouldCapture()` gained `startHour: Int = WINDOW_START_HOUR` and
  `endHour: Int = WINDOW_END_HOUR` params (defaulted, so any other caller not yet updated still
  compiles with legacy behavior). Window check is now
  `now.hour >= effectiveStart && now.hour < effectiveEnd`. Added a private `resolveWindow()`
  that clamps to the legacy 11/18 window when the input is invalid: `startHour !in 0..23`,
  `endHour !in 1..24`, or `startHour >= endHour`. `WINDOW_START_HOUR`/`WINDOW_END_HOUR` constants
  kept as the fallback values (re-purposed from "the only window" to "the safe fallback window").
  0/24 (`startHour=0, endHour=24`) passes validation normally (`0 in 0..23`, `24 in 1..24`,
  `0 < 24`) and works correctly because `now.hour` is always `0..23`, so it captures at every hour
  with no special-casing needed.
- `app/src/main/java/com/jaac/avoqado_tpv/core/data/workers/PromoterLocationWorker.kt`
  **Touched beyond the original "touch ONLY" list** — necessary because this is the actual call
  site: without wiring `settings.promoterLocationStartHour` / `settings.promoterLocationEndHour`
  into the `shouldCapture()` call, the new gate params would only ever get their hardcoded
  defaults and the feature would be inert at runtime (tests would pass, production would not
  change behavior). Also updated the class doc comment to stop stating a hardcoded [11:00, 18:00)
  window.
- `app/src/test/java/com/jaac/avoqado_tpv/core/location/PromoterLocationGateTest.kt`
  `capture()` helper now takes `startHour`/`endHour` (defaulting to
  `PromoterLocationGate.WINDOW_START_HOUR/END_HOUR`). Added 13 new cases: 0/24 window (3am,
  midnight, 11pm all capture), custom 9–21 window (9am captures, 8am doesn't, 8pm captures, 9pm
  doesn't), explicit "absent params default to legacy 11–18" case, and 4 invalid-window clamp
  cases (start>=end, start out of range, end out of range, end=0 non-sentinel) each asserted both
  inside and outside the legacy 11–18 fallback window. All 7 pre-existing tests kept unchanged and
  still pass.

## Defaults / clamp summary
- Server omits the fields (old server) -> DTO `null` -> domain `11`/`18` -> legacy behavior.
- Server sends `0`/`24` -> 24h capture window (validates fine, no sentinel special-case needed).
- Server sends an invalid window (`start>=end`, `start<0`, `start>23`, `end<1`, `end>24`) ->
  `PromoterLocationGate.resolveWindow()` silently clamps to 11/18 rather than never/always
  capturing or throwing.
